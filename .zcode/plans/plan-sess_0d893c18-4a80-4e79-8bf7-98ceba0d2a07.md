## Context

用户要求：做更多动画 + 使用多线程。当前应用是单线程 winit 事件循环，动画驱动依赖 dirty 标志 + `animating()` 检查；设置保存同步写盘。渲染受限于 glutin/Skia surface 非 `Send` 必须留在主线程，因此多线程用在动画驱动和磁盘 I/O 上，动画本体在帧构建层扩充。

## 一、新增动画（全部在 `src/app.rs` 帧构建层，复用 `theme::mix`/`ease_out`/`Smooth`）

1. **主题/强调色交叉渐变**：切换主题或强调色时，旧调色板 → 新调色板 ~0.3s 插值（新增 `palette_fade: Option<(Instant, Palette)>` 字段；`pal()` 返回插值结果，`tick()` 清理，`animating()` 纳入判断）
2. **开始屏滚动惯性**：拖拽释放时记录速度，指数衰减滑行（`start_scroll_vel: f32`，CursorMoved 记录、Released 启动惯性、tick 衰减）
3. **历史面板条目瀑布滑入**：面板打开瞬间起，每条记录按索引延迟 ~25ms 从右侧滑入淡入（基于 `history_open` 的开启时刻 + ease_out）
4. **设置页分区入场**：语言/主题/强调色/数据/关于各分区依次浮现（复用入场动画模式）
5. **顶栏标题过渡**：换页时旧标题淡出+左移、新标题淡入（利用现有 `page_switch` 窗口）
6. **涟漪扩大到全部按钮**：现在只有计算器按键有涟漪，扩展到开始屏磁贴和顶栏按钮（Metro 惯例）

## 二、多线程（`src/app.rs` + 少量 `src/main.rs` 不动）

1. **动画驱动线程**：`resumed()` 创建窗口后 spawn 常驻线程，持有 `Arc<Window>` 克隆 + 共享 `Arc<AtomicBool>`。循环：睡 ~8ms → 若 ANIMATING 置位则 `window.request_redraw()`。主线程 `render()` 末尾把 `animating(now)` 结果写入该原子布尔（替换现在的 `self.dirty = true` 自驱动）。真·跨线程驱动帧率；进程退出时随 main 一起终止，无需显式 join
2. **设置写入线程**：启动时 spawn 专用 writer 线程，`std::sync::mpsc` channel 接收 `(PathBuf, String)`；`save_settings()` 只序列化 JSON 后发 channel，磁盘 I/O 全部离开 UI 线程，单写入者天然避免写竞争
